# Sub2API 手动刷新与响应体超时修复

## 目标与范围

修复已确认的两条路径，不改原生 OpenAI、herdr、认证隔离、配置默认值或 401 即时重试策略，不增加依赖。

- 手动额度检查成功后，沿用自动路径的发布逻辑恢复 refreshMs（默认 180000ms）刷新和适用的 60000ms 倒计时。
- 手动额度检查失败后，恢复既有 30000ms 退避后的自动检查；不新增手动命令内的即时重试。
- 登录及管理员额度请求的默认 15000ms 截止从 fetch 发起持续到 JSON 读取完成；调用方取消在读取期间仍然有效。
- 成功、HTTP 错误、无效 JSON、超时及取消都清理请求定时器；取消/超时不能被当作 JSON 格式错误或成功结果。
- 模型切换、关闭或较新检查使旧检查失效后，旧结果不得发布状态、通知或重新安排定时器。

## 根因与方案

src/statusline.ts 的 runManualCheck 清理两个定时器后，仅直接 setStatus；自动路径 publishResult 才负责重新调度。失败分支也未重新调度。
src/auth.ts、src/sub2api.ts 的 finally 仅围绕 fetch，早于 response.json 清理超时。

采用既有调度函数和覆盖完整请求读取的 try/finally，保持公开函数签名和原有错误分类。
不新增独立的轮询器；不另建 HTTP 客户端或通用请求框架，因为现有函数已具备取消控制和超时参数。

## 验收

先以回归测试证明当前代码失败，再逐项修复；覆盖成功后的定时刷新/倒计时、失败恢复、切换/关闭时的迟到结果，以及真实本机 HTTP 流式响应体的超时/取消。
最后运行类型检查、完整测试和 diff 检查，并同步 sub2api-usage 行为档案。
