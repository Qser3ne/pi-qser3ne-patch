# 统一 pi-qser3ne-patch 插件与仓库

## 意图与范围

将 pi-daybreak 和 pi-token-speed 合并进 pi-qser3ne-patch，形成一个维护仓库、一个 Pi 包和一个扩展入口。用户已选择保留两个旧仓库的提交历史，并要求推送远程、更新本机 Pi 配置。

## 方案比较

1. **单入口、内部模块化（采用）**：src/index.ts 初始化现有额度/双账号功能、内置 pi-usage、Daybreak 和速度统计。统一安装、依赖和测试，真正只加载一个扩展。
2. 一个包保留多个扩展入口：迁移更少，但仍加载多个插件，不符合单插件目标。
3. 只复制源码、不合并历史：提交图简单，但不符合用户选择的历史保留要求。

## 结构与兼容

- Daybreak 与速度统计作为 src 下内部模块迁入；原测试及集成测试同步迁入，统一测试命令。
- vendor/pi-usage 保持现有可复现生成方式及许可证，但由统一入口调用，不再在 pi.extensions 单独声明。
- 保留 /daybreak、/fast、/usage、/openai-usage、/sub2api-usage；保留状态 key、会话自定义条目类型、配置文件名和账号隔离。
- 不新增功能，不改变默认开关或模型选择；Daybreak 的提供商与端点白名单保持原行为，不自动增加第二账号支持。
- 统一开发依赖，兼容 Daybreak 当前 Pi 1.5.0 测试基线；运行时继续使用宿主 Pi，不捆绑宿主。
- 请求事件按既有顺序组合，验证 Daybreak 参数、Fast service_tier 和速度计时互不覆盖。

## Git 与发布

- 在工作区外备份三个子仓库和父仓库 Git 历史、本机 settings.json，保留可回滚资料。
- 以目标仓库为主线，通过保留父提交关系的历史合并纳入两个源仓库当前 HEAD（包含 Daybreak 尚未推送的提交）；代码整理后不保留嵌套 Git 仓库。
- 父仓库移除两个旧子模块声明与 gitlink，仅保留 pi-qser3ne-patch，并更新说明。未跟踪的 .pi/ 不纳入提交。
- 验证通过后先正常推送目标仓库，再推送父仓库；不强推，不删除或归档旧 GitHub 仓库。
- 更新本机 Pi 安装至目标仓库新提交，移除独立 Daybreak、速度统计加载来源。保留独立 pi-usage 的禁用入口配置和其他用户配置。
- 当前会话不强制 /reload，最终提示用户重载以加载新插件。

## 验收

- npm ci、TypeScript 类型检查和完整单元/集成测试通过。
- 真实 Pi 包加载器仅发现一个入口；全部命令各注册一次，第二账号提供商注册一次。
- 新增组合回归测试，验证请求参数保留、事件处理器共存以及状态清理。
- 两个源仓库原 HEAD 均是目标最终 HEAD 的祖先。
- 父仓库无旧子模块引用，统一源码不依赖旧目录；Git 远程提交与本地一致。
- 本机配置仅保留统一包来源，安装副本提交与发布提交一致，实际资源发现无重复入口。

## 风险与边界

开发依赖版本不同可能暴露兼容问题，必须通过全部既有测试后发布。认证凭据、模型覆盖、真实服务请求均不属于本次修改；验证使用模拟传输，不调用真实账号。不处理或提交父仓库中无关的 .pi/ 文件。
