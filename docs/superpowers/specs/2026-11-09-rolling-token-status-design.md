# 近 24 小时 token 状态栏设计

## 目的与范围

在现有主状态栏的上下文窗口之后、时间之前显示滚动近 24 小时 token 总量和缓存命中率，方便随时查看本机用量。统计范围由用户选择为与 `/token 24h` 一致：跨项目、跨会话，仅包含当前 `/model` 默认模型列表；使用 scopedModels，未设置时使用 modelRegistry.getAvailable()。这不是服务商账单，也不包含本机未保存的历史。

## Approaches

1. **集成兼容状态栏（用户选择）**：在 pi-qser3ne-patch 内保留带来源和许可证的 pi-statusline 0.50.2 兼容实现，增加原生段，继续读取 pi-statusline.json 并保留 /statusline。禁用独立包扩展入口，避免 footer 和命令冲突。优点是位置、样式和响应式布局可靠；代价是维护兼容副本。
2. 普通 setStatus 状态项：维护成本低，不接管 footer，但只能在扩展状态行显示，不能满足指定位置，未选。

不直接修改 node_modules，不解析或替换渲染后的屏幕文本，不引入依赖同级开发目录的运行时导入。

## 显示与统计

用户修正后的示例：`🪟 ctx 42.0%/272k · 📊 12.3M CH 85.2% · 🕒 16:42`。以一个图标代替 24h 文字；📊 是实现方建议的默认图标，统计仍为近 24 小时。颜色、分隔符、其他段和其他扩展状态沿用现有配置。新段默认插入 context 后（通常即 time 前）；以后可通过 /statusline 自定义布局调整。

复用 pi-token-usage 当前固定版本的纯统计模块，并保留版本来源，避免新增 /token 命令或重复初始化该扩展。总量使用统计报告 totalTokens；缓存率使用窗口总 cacheRead / (input + cacheRead + cacheWrite)，不是逐次百分比平均，也不把输出放进分母。沿用已有会话记录、子代理协调和去重规则，复用磁盘快照缓存路径及格式。

无用量时显示 `📊 0 CH —`；初次加载显示 `📊 …`；失败显示不可用，存在不完整统计警告时显式标记，不能伪装为准确的零。

## 刷新与边界（实现选择）

仅在 TUI 工作；启动/会话切换/模型切换刷新，完成轮次或 agent 结束后合并触发刷新，另每 60 秒刷新以移出过期记录并观察其他会话。扫描异步进行，不在 render 内扫描，不为每个流式 token 刷新；使用 single-flight、合并事件和会话代际保护，退出清理定时器。终端变窄时沿用响应式裁剪，优先保留上下文。

不改变 quota、速度、Daybreak、Fast、herdr、/token 等现有功能。独立 pi-token-usage 保持启用。集成后仅在原有无 footer 覆盖约定中为该兼容状态栏增加明确例外。

## 验收与交付

测试统计口径、格式、插入顺序、窄屏、配置兼容、异步刷新与清理、单一命令/入口及生产依赖加载；执行 typecheck 和全套现有测试。更新 README、CHANGELOG 和行为档案。

本轮先修改开发仓库；不会默认推送远程或更新固定 Git 安装副本。实际启用时需安装本地开发包或更新固定 Git 来源，并把独立 pi-statusline 配成 extensions: [] 后 /reload；未部署前不改动正在使用的全局配置。
